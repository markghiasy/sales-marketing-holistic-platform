# 让关系证据服务商业战略决策

**值得做，但研究对象应是“目标驱动的战略关系画像”，技能只是其中一面。** Mark 和老板更可能问：谁有相关需求、哪家公司适合试点、谁能提供渠道、通过谁进入目标组织、现在为什么值得联系。建议把人和组织的证据档案、随时间变化的商业情境、真实接触路径、针对本次目标的匹配分开。成熟研究分别提供组织角色、来源追踪、专家检索、网络桥梁和子图检索方法；本次没有发现一个现成方案能直接从私信可靠地产生完整商业画像。以下是基于这些方法的工程建议，**尚未实现战略画像，也没有本项目效果实验**。研究核对日期：2026-09-28。

## 画像回答“此时对这个目标有什么作用”

静态的“金融、工程、领导力”标签不足以回答战略问题。组织购买本身涉及多种参与者、组织条件与决策过程，不能缩成一个联系人的偏好或职位。W3C ORG 也把人、组织、角色和任职关系分开，并明确组织结构不完整表达授权与控制。因此“Director”不能自动成为本次采购的批准人。（[Webster 与 Wind](https://faculty.wharton.upenn.edu/wp-content/uploads/2012/04/7215_A_General_Model_for_Understanding.pdf)；[W3C ORG](https://www.w3.org/TR/vocab-org/)）

建议四层共同构成画像，而非一张越来越长的个人标签表：

| 层 | 保存或计算什么 | 业务问题 |
|---|---|---|
| 事实与经验 | 人、组织、任职、服务、市场、项目贡献、行为事例，均附证据 | 谁做过类似事，组织提供什么？ |
| 当前商业情境 | 明确需求、initiative、约束、评估阶段、时间窗口、承诺、特定决策角色 | 为什么现在值得谈？ |
| 关系与接近路径 | 合作、介绍、往来事件、联系渠道，以及本次介绍意愿 | 如何接近，哪一步还需确认？ |
| 目标相关性 | 本次潜客、伙伴、渠道、资源方、引荐人等候选角色 | 对这个目标有什么帮助，下一步问什么？ |

前两层都允许以**组织或 initiative 为主体**，不能把公司的需求和资源全部归给发信人。某人任职投资机构不证明个人可投资；公司有客户渠道不证明员工有权开放；过去帮忙介绍不证明这次愿意介绍。Burt 的结构洞研究支持寻找跨群体信息入口，但图上的桥梁位置不能证明意愿、权限或成功率。（[Burt 2004](https://snap.stanford.edu/class/cs224w-readings/Burt04StructureHole.pdf)）

技能可按需对接 ESCO，安全项目任务可参考 NICE；NICE 特别区分工作角色与职位。它们帮助统一名称和拆任务，不验证联系人真实水平。软实力先展示“协调过三方评审”等有情境的行为；“great leader”保留为他人评价。沟通量、交付次数和人格评分不能互相替代。（[ESCO](https://esco.ec.europa.eu/en/classification/skill-main)；[NICE](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center/resources/occupations-jobs-and-work)）

## 成熟部件可以组合，先不换整个后端

| 路线 | 适合之处 | 本项目取舍 |
|---|---|---|
| CRM 字段、标签、静态摘要 | 已知条件过滤，人工维护直观 | 保留基础筛选；不足以表示转述、过期与目标变化 |
| 原文优先检索，再归人/组织 | 能发现尚未进入画像的信息 | 与结构化断言并行，防止画像遗漏限制召回 |
| 有来源、时间与情境的断言图 | 能解释需求、角色、资源与修正 | 推荐作为底座，先用现有 Postgres |
| GraphRAG、预算子图算法 | 大语料综合、多跳与连接预算 | 作为后续比较方案，不先引入完整系统 |
| 技能覆盖与团队选择 | 技术实施、互补组队 | 仅在用户确实要组队时启用 |

原文优先路线有专家发现研究基础：Balog 等先找相关文档、再聚合文档与人的关联，在其 TREC 实验中优于先合并人物文档的模型；它仍依赖正确归属，不能把正文技能授予发信人。（[SIGIR 2006](https://krisztianbalog.com/files/sigir2006-expertsearch.pdf)）GraphRAG local search 组合实体关系与原文；G-Retriever 研究有预算的相关子图。这些解决检索问题，不自动解决购买权、引荐意愿或业务机会真实性。（[GraphRAG local search](https://microsoft.github.io/graphrag/query/local_search/)；[G-Retriever](https://arxiv.org/abs/2402.07630)）

本轮代码核对显示，合成 demo 有 **26 条 function/industry 画像断言和 5 条工作记录**；已有来源、时间、完整路径打包和缺口状态。当前人选召回仍为规范化词项 OR，coverage 是文本匹配，不是能力或商业资格验证。生产事实结构有来源、状态、模型版本等字段，但本轮检查未见完整战略情境模型。早期检索报告中的“按活跃度/ID 截断”等描述已被后续优化替代，不能继续当作现状。（[fixture](../../../tests/fixtures/network_demo.json)；[retrieval](../../../adapters/network/retrieval.py)；[生产事实表](../../../db/migrations/0005_identity_resolution.sql)）

## 最小模型保存“谁在什么情境下声称什么”

推荐轻量组合 ORG 的角色结构与 PROV 的来源思想；无需采用 RDF 数据库。PROV 表达生成、归属和派生，不保证内容真实；原文定位可借鉴 Web Annotation 的精确引文选择器。（[PROV-O](https://www.w3.org/TR/prov-o/)；[Web Annotation](https://www.w3.org/TR/annotation-model/#text-quote-selector)）

| 对象 | 最小内容 |
|---|---|
| Entity | 人、组织、项目/initiative；复用身份解析 |
| Evidence | 消息/工件 ID、原文片段、作者、来源链、时间、重复组、可见范围 |
| EvidenceAssertion | 类型、主体、关系、对象、情境、证据、主张者、否定/计划状态、审核/冲突状态 |
| BusinessContext | initiative、所属组织、需求、目标、阶段、约束、窗口、下一步；字段引用断言 |
| GoalMatch | query ID、要求、候选角色、支持/相邻/冲突/未知、路径、缺口、建议验证问题 |

任职、决策参与、介绍、提供资源都可用类型化断言表示；先选 demo 所需的小词汇，不另建完整销售 CRM。保留消息时间、系统获知时间、事实有效期及修正记录。职位离任终止当前权限，不抹去历史经验；预算窗口比行业经验更需要近期确认。过了建议复核日表示“待确认”，不是自动判假。

流水线应为：**去重并识别引用 → 分清作者、主张者与实际主体 → 抽取原子断言及时间/否定 → 原文校验与人工修正 → 生成各视图投影**。例如“朋友公司想做审计”属于朋友公司的需求；“我想学安全测试”属于兴趣；“我们团队交付了”不能给每个成员挂独立交付能力。FactBank 的来源相对事实性研究说明，同一事件在不同说话者视角下可具有不同确定性。（[FactBank](https://catalog.ldc.upenn.edu/LDC2009T23)）

原文检索与断言检索必须并行，实体合并/撤销、证据删除或修正后重算相关投影。重复转发只算同一来源组。没有消息表示**没有观察到**，不表示没有能力、需求或关系；同时呈现渠道和时间覆盖，避免资料多的人天然胜出。

## 搜索生成机会子图，而不只生成一队人

入口保留一个问题框。用户输入目标后，先出现可编辑的需求 chips，明确区分用户原话、模型推断和建议补充。系统判断本次是获客、渠道、资源、组织进入还是组队，再逐需求召回原文与断言，检查主体、时间、情境和证据是否足以支持要求。相邻经验可作为线索，未知不能满足硬要求。

结果应同时返回**候选机会、人/组织、完整接触路径、尚待验证的假设与下一步问题**。商业机会按目标需求与资源匹配、时机依据和接触路径解释排序，不把所有人强行组成团队，也不显示永久“商业价值分”。只有交付组队才做互补覆盖选择；技能覆盖与社会沟通成本的组合已有经典研究，不是本项目的新发明。（[Lappas 等，KDD 2009](https://cs-people.bu.edu/evimaria/cs591/lappas09finding.pdf)）

给 Mark 的合成 demo 可以问：“我想把 AI 安全产品带入物流市场，找到首批试点和渠道伙伴。”图上出现一家明确提过相关问题的物流企业、负责本次技术评估的联系人、过去介绍过双方的桥梁、表达过合作范围的渠道方。旁边保留“预算批准人未知、试点数据权限未确认、桥梁本次是否愿意介绍未知”。下一步建议是问清试点条件和决策流程，而不是宣布找到了买家。技术专家是其中一个支持角色。

动画按真实阶段展现：需求 → 候选 → 支撑项目/业务情境 → 接触路径 → 缺口。**已存事实边与本次匹配建议边分别绘制**；后者不写回永久关系图，共同公司不能画成相识。允许图有不连通部分，缺口显示为要求卡片。点击任一推荐可回到原文；重播动画不需要重跑模型。

## 先验证商业案例，再决定论文贡献

第一阶段用合成消息补齐“物流试点、渠道合作、目标组织进入”三个场景，以及离职、预算用完、转述需求、条件性介绍等反例，实现上述最小 schema、统一入口和目标子图。第二阶段用经授权的小批真实通信双人标注，优先验证主体归属、需求、角色、时间和介绍状态，再决定需要哪些领域词表与混合检索。第三阶段固定测试集比较标签/筛选、静态 LLM 摘要、原文检索、证据时态画像；控制同一模型、材料和预算，消融时间、归属、路径类型及未知处理。

论文可研究：**在不完整的商业通信中，目标条件化、带来源与时间的画像，是否改善可证据支持的战略检索，并减少虚构决策权、购买意向与引荐意愿？** 测每项需求的召回、机会证据精度、错误权限/意愿断言率、过时需求引用、完整路径率、未知识别、成本与延迟；让 Mark 盲评下一步是否值得做，不能只靠 LLM 自评。

公开数据只能验证部件。TREC 提供专家及支撑文档相关性标注；SkillSpan 是招聘文本技能抽取，均不等价于私信中的商业机会。真实测试按线程、项目和重复来源组隔离，再测时间外推，避免同一事实副本泄漏。合成 demo、回归测试和少量 API 成功调用不能证明工业效果；成交提升更需要长期验证。（[NIST TREC](https://trec.nist.gov/data/t15_enterprise.html)；[SkillSpan](https://aclanthology.org/2022.naacl-main.366/)）

最有价值的产品输出可能不是“我找到了最合适的人”，而是“这三条机会值得验证，先问这两个问题”。这让资料缺口成为下一次行动的依据。潜在研究贡献在可检验的证据语义与评估，而非把 LLM、标签和图连起来；新颖性仍需更完整相关工作和实验确认。
