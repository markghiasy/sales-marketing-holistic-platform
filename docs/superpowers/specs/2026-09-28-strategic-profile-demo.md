# Strategic profile experiment

Approved direction: the user asked to try the researched strategy profile approach. Build a synthetic commercial scenario using existing people/organizations; no production DB ingestion, scraping, outbound messages or deployment.

Outcome: one search input can handle a business goal; a light animated opportunity subgraph explains matching evidence; entity lenses expose strategic assertions and a review workflow. A bounded Claude extraction call can propose assertions from authored synthetic source messages. Recommendations never become permanent graph relationships.

EvidenceAssertion fields: id, subject_id, facet (experience/need/resource/decision_role/relationship/constraint), label, context_id (existing entity ID or empty), basis (self_declared/reported/observed), observed_at, valid_from, valid_to, status (pending/confirmed/rejected), evidence_ids and exact quote. Metadata claimant_id/model are retained. Dates and all sources must be known at query time; pending/rejected claims cannot enter answer retrieval. Source existence and exact quote are mechanical validation, not semantic proof. Extraction always proposes pending records. Human review can correct subject and confirm/reject, with optimistic version check and audit. Review/extraction is local in-memory demo state and resets on restart/reset; say so in UI.

Use existing Atlas Logistics, Harbour, Northline and existing contacts. Illustrate a logistics AI security pilot need, technical evaluation role explicitly without budget authority, channel resource offer with conditions, past experience, expired initiative, and a third-party need attributed to organization rather than author. Source records are explicitly synthetic; pre-reviewed fixtures are authored examples, not successful LLM extraction.

Goal map: actual eligible relationship edges distinct from dashed query-to-entity lexical candidate edges; never imply skill/need qualification or introduction willingness. Restrict nodes/edges to evidence pack with complete relationship endpoints; bounded rendered size; requirements with no evidence remain visible gaps. Preserve time/mode. Respect reduced motion.

No new dependencies, current light styles (white, slate, muted purple/teal). Browser/API error paths must be understandable. Same-origin validation and paid-call session budget reused for extraction. Unknown HTTP bodies fail safely.

## Follow-up relation semantics (user steering)
Current 1-3 hops count graph edges, not familiarity. Introduce a separate four-band conceptual view later: direct interaction; evidenced collaboration/introduction; shared project/team context; broad organization/company context. Shared membership never certifies acquaintance; organization and company do not have a universal strength ordering. Keep actual path length explicit. This experiment labels relationship vs query-candidate edges and preserves current hop controls; it does not silently redefine hop depth.
