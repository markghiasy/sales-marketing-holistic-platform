## 选择与原因

选择 **现有 PostgreSQL 源数据只读适配 + 同一数据库独立 network 派生 schema + 独立本地试用服务**。

沿用已评估的 PostgreSQL 候选与现有 psycopg 依赖；Mark 不增加 Neo4j、Docker 或本机数据库服务。读源连接强制只读，派生层写连接的所有业务写入限定到独立 schema。初始化步骤显式执行且仅创建/升级派生 schema，不运行全部历史 source migrations。数据库账号与目标 schema 能力必须通过预检；权限不足时给出明确问题，不自动更换连接或提升权限。

这是一项设计选择，不声称 PostgreSQL 对所有图工作负载都最快。源库有额外存储和索引负担，需要在 Eva 真实规模与 Mark 参考规模的合成数据上测量。同库不是同事务生命周期：worker 通过源指纹和原子派生版本处理一致性，不修改 identity/message/fact 等来源业务表。

另外两个选择：SQLite sidecar 不需新增源库 schema，但尚无本项目规模验证，且与最新存储评估的候选不同；直接覆盖现有 Inbox 的运行实例会把接入验证与升级风险混在一起。首轮先独立服务，保留已存在的 Inbox/采集服务。

## 交付内容

1. **真实数据 Network 页面与嵌入切片**：复用已有浅色图、选择、四范围和证据交互。试用服务提供只读联系人/对话视图承载切片与搜索；既有 Inbox 保持原运行入口，不在本轮顺带迁移其摘要管线。
2. **图数据适配**：有 person_id 的身份使用稳定 canonical ID，其余身份独立存在；不按同名合并。直接往来、组织关系从可用结构化来源生成；群发收件人不自动两两认识。
3. **多标签及画像审核**：来源支持、时间和审核控制同一套投影；审核结果、拒绝和来源版本持久化。旧 ai_brief.graph/summary 只能作标明来源与更新时间的缓存内容，不能提升为已核实图事实。
4. **项目、合作、介绍及战略画像**：没有已入库事实时显示证据缺口。对选定联系人/一批有限消息进行显式模型抽取，生成待审核的实体/关系/画像建议；新项目需有定位原文与实体确认，不按主题或名字猜测身份。审核后才能进入正式图和标签。项目活动来自有证据的记录，不自动生成生产力排名。
5. **检索与策略问答**：先以索引候选限缩上下文，避免全网 catalog 和全量重建。沿用现有 Anthropic 配置与预算；不引入新 embedding 供应商。支持真实引用、未知条件和清楚的失败状态；模型不可用时基础图与词法检索仍可用。
6. **持续刷新与恢复**：新消息按入库时间与 ID 游标读取，重复导入幂等；定期对账捕获纠错、隐藏、合并/撤销和删除。源删除或重映射使依赖图/标签/检索失效，人工审核历史仍保存。提交派生版本和处理进度原子完成。

能力随真实证据而定；“具备 demo 交互”不承诺所有人立刻拥有完整能力画像或项目记录。全历史批量画像抽取默认关闭，先用有额度的选定范围验证。

## 接口与版本边界

- `SourceRepository`：分页快照、增量消息、元数据与完整清单对账；只选明确字段，不读取 message.raw；兼容没有 ai_brief_status 的既有源库。
- `NetworkStore`：独立 schema 存储来源镜像/指纹、派生断言、审核事件、索引、待处理工作与水位；数据目录和日志不得含可发布真实内容。
- `NetworkService`：提供版本化图、候选查询、证据、画像、审核及健康状态，复用 synthetic UI 契约；真实模式不存在 fixtures fallback、模拟回复/reset 路由或固定示例日期。
- `NetworkWorker`：单实例、有批量上限与恢复机制；浏览器打开不创建额外 worker。60 秒增量轮询、5 分钟元数据检查、15 分钟完整对账作为初始可配置值；通知可加速但不能作为唯一可靠信号。
- `NetworkAgent`：输入候选和证据版本；发送前及发布前复核相关来源/身份依赖。被修改的旧回答不能无提示发布，无关新消息不必使整条回答失败。
- 当前与历史查询区分现实事件时间和系统获知时间；没有保存历史的字段不伪造精确历史。真实模式默认使用当前时间，不复用 demo 的固定日期。

采用显式受限读写职责，并增加“派生写入不得落到源业务表”的测试。首次 schema 初始化由专用命令承担；命令必须检查版本和目标绑定，不能通过忽略 DuplicateTable 错误假装迁移完成。

## 验收顺序

1. 隔离数据库与 fake 模型测试：来源兼容、同名/未解析身份、群发边界、同步幂等、重启、事务失败、纠错失效、审核不丢、图/搜索/标签同版本。
2. Eva 真实库只读预检：聚合计数、schema 能力、canonical owner/source 指纹和当前服务绑定；只记录非敏感诊断。
3. 准备明确的派生 schema 初始化与恢复步骤，在 Eva 配置上启动候选服务，避开 5000、5001 和已有 demo 端口。
4. 基础真实图、词法搜索和来源验证通过后，进行有明确预算的真实模型小样本验证与人工核查。
5. 验证新增消息、源更正/隐藏/删除、模型超时、断连和重启；测正常负载与 Mark 参考规模下的耗时。界面报告实际 freshness；不把轮询频率写成端到端 SLA。
6. 干净安装检查，并记录 Windows 实测与尚待 Mac 现场确认的区别。

如果到周四仍未通过某条关键数据正确性/恢复验收，不把它标为完成；明确给出实际可试用范围和剩余缺口。周五是交付目标，不以时间压力绕过验证。
